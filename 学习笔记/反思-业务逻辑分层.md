## 二、异常：按「哪一层抛的」分（一张表）

> 之前那版把「层」和「异常来源」两套维度混着列，互相映射不上。统一成一张表。

| 层级 | 典型异常 | 谁负责接 | 用户看到什么 | 我项目里的例子 |
|---|---|---|---|---|
| 前端 `fetch` | 断网 / DNS / 超时 | `streamChat` 的 `catch` | 气泡「网络异常：…」 | `chat-api.js:59-61` |
| 前端状态码 | 401 / 422 / 500 | `res.status` 判断 | 401 → 提示 + 跳登录 | `chat-ui.js:42-44` |
| 前端解析 | JSON 解析失败 | `createParser` 里的 `try` | 当错误事件处理 | `chat-api.js:42-48` |
| 入口（FastAPI） | `RequestValidationError` | **框架** | 422 + 字段详情 | 请求体不合规时 |
| 入口（FastAPI） | `Depends` 里 `raise HTTPException` | **框架** | 401（认证）/ 429（限流） | `dependencies.py`、`rate_limit.py` |
| 路由 / 业务 | 会话不存在、或不属于你 | `raise HTTPException(404)` | 404 | `main.py:302-310` |
| 数据访问 | `IntegrityError`（唯一/外键冲突）、`OperationalError`（表/列不存在） | 路由的 `try`（或让它爆） | 500 | 删会话时的外键约束 |
| **上游（流已开始）** | `TimeoutException` / `RequestError` / 非 200 / 解析失败 | **生成器内 `except` → `yield` 错误事件** | 气泡「模型服务…」 | `main.py:361-368`、`:411-417` |

### ⚠️ 最特殊的一条：上游异常在「响应头已发出」之后

这是**流式接口独有的规则**，也是我 10-04 亲自踩过的坑：

- **响应头发出之前**（还在 `gen()` 外面）→ 可以 `raise HTTPException`，它会变成真正的 4xx/5xx
- **响应头发出之后**（200 + `text/event-stream` 已下发）→ **`raise` 改不了状态码，只会掐断连接** → 用户看到「200 然后莫名断流」
  → 只能 `yield` 一条**流内错误事件**，再补 `data: [DONE]`

配套两个坑：

1. `try:` 必须包住**两个** `async with` —— 写在 `client.stream(...)` **里面**等于死代码（连接阶段的异常在 `__aenter__` 抛，接不住）
2. `TimeoutException` 是 `RequestError` 的**子类** → `except` 顺序不能反

### 关于事务与 `rollback`

`with SessionLocal() as session:` **已经兜住了**：块结束时没 commit 的事务会被回滚、连接归还。

所以：

- **平时不需要**手写 `session.rollback()`
- 只有**提交失败后还想在同一次 session 里继续操作**时，才需要显式 rollback 清掉失败状态
- 到处加 `rollback()` 反而掩盖真正的错（本来该崩的，变成静默继续）

### 系统异常：开发期 vs 生产期

| | 开发期 | 生产期 |
|---|---|---|
| 未捕获异常 | **让它爆 500**（越响越好，你才看得到） | **接住 + 记日志（带堆栈）+ 返回统一文案**（别把堆栈/内部信息透给用户） |

> 之前那版只写了开发期，生产期没闭环。

## 三、日志

### 格式约定（现在是中英混杂，统一一下）

```
[模块] 做什么: 关键id / 关键值
```

例：

- `[title] 会话 12 → 接口限流实现`
- `[title] 失败: 会话 12 / TimeoutException`
- `[DeepSeek error] 上游返回 500: {...}`
- `[解析失败] data: {...}`

**为什么要有约定**：出问题时你是**拿关键字搜日志**的。前缀统一，`grep "[title]"` 就能捞出这个模块的全部记录。

### 开发期 / 生产期

| | 开发期 | 生产期 |
|---|---|---|
| 形式 | `print`（uvicorn 控制台） | 结构化（JSON）+ 级别（INFO / WARNING / ERROR） |
| 去向 | 控制台 | 落盘 / 采集 |
| 打什么 | 关键分支 + 失败原因 | 同上，但**必须带请求上下文**（谁 / 哪条会话 / 哪次请求） |

## 四、核心原则

### 1. 分层

- 上层调下层，**下层不感知上层**
- **真判据不是「每层只做一件事」，而是「这段代码依赖什么」**：
  - **只依赖入参文本** → 纯函数层
    例：`generate_title(api_key, user_message, ai_reply) -> str | None` —— 不碰 DB、不读环境变量
  - **依赖 DB / 调度 / 配置** → 副作用层
    例：`_fill_title` —— 开 session、查会话、写 title、兜异常
- 副作用层**调**纯函数，不是反过来
- **现状偏差**：`generate_title.py` 里同时写了 `_fill_title`（副作用）→ 要么把 `_fill_title` 挪回 `main.py`，要么接受"这是一个标题模块"。**两种都行，但要知道自己选了哪种。**

### 2. 异常

- 业务异常 → `raise HTTPException(状态码, detail)`
- 系统异常 → 开发期让它爆；生产期接住 + 记日志 + 统一 500
- 事务异常 → 靠 `with session`（见上文），别乱加 `rollback`
- **`CancelledError` 不是 `Exception` 的子类**（3.8+ 起继承 `BaseException`）→ `except Exception` **抓不到取消**，这是**有意设计**（取消不该被吞）
  - 推论：`create_task` 出去的任务被取消时，异常会冒到任务层 → 要么在 `add_done_callback` 里看，要么按 best effort 当它没发生

### 3. 安全

- **前端校验不是安全边界**（前端拦得住的，`curl` 一定能绕）
- 后端**必须校验归属**：`WHERE id = ? AND user_id = 当前用户` —— **读和写两条路径都要**
- 敏感信息不进前端（API Key 只在后端读一次）
- **资源不存在 / 不属于你 → 都返回 404**（403 会泄漏「这个 id 存在」→ 可枚举）
  - 判据：**这个资源的存在性本身是不是敏感信息**？是 → 404；否 → 403

### 4. 异步

- **`await` 是暂停点**（解决"CPU 别空转"）；**`create_task` 是新增一条执行线**（解决"我别干等"）—— 两者是**配合**，不是替代
- 协程里**不能有同步阻塞**（`time.sleep`、大的同步查询会把整个事件循环饿死）
  - **现状偏差**：`with SessionLocal()` 是**同步** Session，放在 `async def` 里会**短暂阻塞事件循环** → 现在规模无感；要讲究就 `await asyncio.to_thread(...)` 或换 `AsyncSession`
- 后台任务的边界 = **best effort**（进程活着才保证跑完；`uvicorn --reload` 一保存就杀）
  - 三个坑：**留引用防 GC** / **异常必须包在 task 内**（没人 `await` 它，否则静默）/ **DB session 要自己开**（外层那个已关）
  - 代价小的（生标题）→ best effort 够；代价大的（订单/充值）→ 必须持久化（哪怕先拿表当队列）

## 五、什么时候才抽 service 层（别提前重构）

**触发条件（满足任一条才抽）**：

1. 同一段逻辑被 **≥2 个路由**用到
2. 单个路由函数 **> 50 行**
3. 需要**单独测**它（跑 HTTP 请求测不动）

**抽的时候也只抽一半**：先挪最独立的那一段。

例：`chat_stream` 里最该先独立出来的是「**取历史 + 裁剪**」—— 它和 HTTP、和上游都无关，纯数据操作。挪成一个函数后，`chat_stream` 只负责编排。

**别一次全搬** —— 一次全搬 = 大爆炸重构，正是**路线发散**的高发区。

## 六、一句话总结

- **分层**：按"依赖什么"分；上层调下层，下层不感知上层；没到规模就别抽 service
- **异常**：按"哪一层抛的"分；流式接口的上游异常**只能 yield**；`CancelledError` 抓不到是故意的
- **日志**：`[模块] 做什么: 关键id` —— grep 得出来才有用
- **安全**：前端不是边界；归属校验读写都要；不确定就 404
- **异步**：`await` = 暂停点，`create_task` = 新增执行线；协程里别阻塞；后台任务认 best effort
