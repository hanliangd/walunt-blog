#### 第一次一定会撞的 5 个坑（按撞见顺序）

| # | 坑 | 症状 → 解法 |
|---|---|---|
| 1 | **流式接口不能挂 `response_model`** | 现在 `/chat` 上那个 `ChatResponse` 要去掉，否则报错/结构不对 |
| 2 | **`httpx.AsyncClient(timeout=30.0)`**（main.py:120 现在就是） | 这是**含 `read` 的总超时**：流式下"30 秒内没来下一块"就 `ReadTimeout`，**症状长得像"模型没响应"** → `httpx.Timeout(30.0, read=None)` |
| 3 | ~~首个 chunk 的 `delta` 只有 `role`、没有 `content`~~ **← 10-03 实测：不成立** | 实测首块是 `{"role":"assistant","content":""}`：**`content` 存在，但是空串**，`delta["content"]` 不会 KeyError。**真正会咬你的是把空串当结束**（写成 `if not content: break` → 第一个 chunk 就退出 → 表现成"一个字都没有"）。`.get("content")` 仍算好习惯（换 `deepseek-reasoner` 会出现只有 `reasoning_content` 的 delta，**未实测**） |
| 4 | **PowerShell 里 `curl` 是 `Invoke-WebRequest` 的别名** | 它会把整段响应**缓冲完**再给你 → 你会看到"没有流"，然后去怀疑后端代码 → **必须写 `curl.exe`** |
| 5 | **错误只能藏在流的内容里** | HTTP 状态码已经发出去了（200），上游出错时不能再返回 4xx/5xx → 只能往流里发一条错误事件 |
| 6 | **`aiter_lines()` 会吐出空字符串**（原计划漏了这条） | 上游每个 `data:` 行**后面跟一个空行** → `json.loads(line[6:])` 在空行上直接 `JSONDecodeError` → 循环开头 `if not line: continue` |
| 7 | **`async with client.stream(...)` 写在生成器外面**（原计划漏了这条） | 路由里开流、再 `yield` 出去 → `async with` 在消费生成器之前就退出 → 拿不到内容 / 报流已关闭 → **必须在 `async def gen()` 内部开**。这次做对了，还白送一个好处：客户端断开时上游连接会被 `async with` 自动关掉 |

- **客户端中途断开**：用户关了页面，服务端还在等上游 → ~~要处理 `asyncio.CancelledError`~~ → **10-04 决定不补**：`async with client.stream` 已经保证上游连接被关；`except` 里 `yield` 没意义（客户端已经走了）；**吞掉它反而破坏取消语义** → 列为观察项
