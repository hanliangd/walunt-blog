## 三、技术栈（定死，不许换）

```
后端    FastAPI + Pydantic + SQLAlchemy 2.0
数据库  SQLite（要上云再换 Postgres）
认证    Session Cookie + Argon2
前端    Jinja2 服务端渲染 + 原生 JS 增强
LLM     一个大模型 API + SSE 流式输出
向量库  Chroma（本地，零部署成本）
部署    便宜 VPS 或 Render
```

### 明确不要碰（在你的时间预算里全是负收益）

React · Vue · TypeScript · Docker · Kubernetes · Redis · 微服务 · 消息队列 · LangChain

不是这些不好，是**现在学它们是负收益**。等项目真的撑不住了再说——那时你已经知道"为什么要用它"。

### 为什么前端选 Jinja2 而不是 React

1. 你现有的 HTML/CSS 几乎零改动就能复用（插 `{{ }}` 变成模板）
2. 一次性解决博客"HTML 是空壳、没 JS 就白屏"的问题
3. 没有 CORS、没有状态同步、没有构建工具、没有 npm
4. **Jinja2 默认自动转义 HTML** —— 这本身就是一堂 XSS 防护课，正好是你的专业方向
5. 学 React 会吃掉你 1/3 的时间预算，而且大概率学成"会用但不知道为什么"

### ⚠️ 这一节留下的悬空项（2026-10-08 记录，2026-10-09 修订）

上面 5 条理由把 **Jinja2 写进了技术栈**，但**全文没有任何一个阶段的「学 / 做」清单里出现过它** —— 它一直是"不学 React 的**理由**"，从来没变成**任务**。

**⚠️ 2026-10-09 修订：不要把 Jinja2 绑到「把后端关掉不白屏」那条验收上 —— 那是错的绑定。**

| 说法 | 判定 |
|---|---|
| Jinja2 能解决"**没 JS 就白屏**"（理由 ②） | ✅ 对。但**不痛**：他的页面本来就靠 JS 渲染，没有"用户禁用 JS"的场景 |
| Jinja2 能实现阶段 1 的验收「**后端关掉 → 显示友好提示**」 | ❌ **错**。那条验收靠的是**防御性渲染 + `fetch` 的 `catch`**（阶段 1「做」里原文就写着"落地防御性渲染，每个模块独立 try/catch"）—— **跟模板引擎没关系**。而且 **SSR 反而更难**：后端挂了，SSR 连 HTML 都返回不了，而静态页至少还能加载出来、再由 JS 显示"服务暂时不可用" |
| Jinja2 的 `autoescape` = 服务端 XSS 防御 | ✅ 对，但**这个知识点现在就能拿**：机制和 Python 标准库 `html.escape()` / `markupsafe.escape()` 完全一样，**不用引模板引擎**。等真上 Jinja2 时只是换个入口 |

**结论（2026-10-09，采纳外部评审意见后修订）**：

- ❌ **阶段 3 收尾时不要碰 Jinja2** —— 不是痛点、不是验收必需、也没有真实需求驱动
- ✅ **挪到阶段 4（RAG）之后**：那时会多出"引用来源页 / 问答页"这类**真实页面需求**，用 Jinja2 改 SSR 就是"**有需求驱动的学习**"（正好呼应第 63 行那句"等项目真的撑不住了再说——那时你已经知道为什么要用它"）
- ✅ **知识点现在补、项目不动**：在 prompt injection 实验的"防御面"那半，用 3 行 `html.escape()` 做对照，把"服务端转义"这一端补上（和前端 `textContent` 是同一个知识点的两端）
- 真到那天要学，就三个点、半小时：`{{ }}` 插值 / `{% %}` 控制流 / **`autoescape`（默认开，别关）**

### 阶段 0 · 让博客活起来

**时间**：大二上 10 月 | 2-3 周

**学**
- Python 环境（用 `uv`，别折腾 conda）
- FastAPI 最小应用、路由、`async def`
- Pydantic 响应模型
- `StaticFiles` 挂载现有 HTML/CSS/JS
- `uvicorn main:app --reload` 热重载

**做**
```python
# main.py
from fastapi import FastAPI
from pydantic import BaseModel

class User(BaseModel):
    name: str
    bio: str
    avatar: str

app = FastAPI()

@app.get("/api/profile", response_model=User)
async def get_profile():
    return {"name": "walunt", "bio": "...", "avatar": "/static/img/..."}
```

`render.js` 改成 `fetch('/api/profile')`。

**验收**：改 Python 里的名字 → 刷新浏览器 → 页面上变了。

**安全点**
`response_model` 不只是文档，它是**白名单**——模型里没定义的字段不会被返回。
将来用户表有 `password_hash`，靠它挡住意外泄露。这是真实项目里最常被忽略的一道防线。

**里程碑**：✅ 我已经自己写过一个 API 并调用成功了

### 阶段 1 · 博客完全 API 化

**时间**：大二上 11-12 月 | 4-6 周

**学**：`APIRouter` 拆分、依赖注入、`HTTPException`、HTTP 状态码、CORS（同源就不需要它，理解为什么）

**做**
- 拆成 `/api/profile` `/api/photos` `/api/music` `/api/posts`
- 前端封装 `fetchJSON()`，统一处理错误和降级
- 落地防御性渲染（每个模块独立 try/catch，互不拖累）
- 删掉 `data.js`

**验收**：把后端关掉，页面显示友好提示而不是白屏。

**安全点**
- 错误信息不泄露内部细节。`HTTPException(500, "数据库连接失败：xxx")` 在生产是信息泄露。对外只说"服务暂时不可用"，细节写日志
- 继续用 `textContent` / `createElement`，零 `innerHTML`

**里程碑**：✅ 一个前后端分离的博客

### 阶段 2 · 数据库 + 认证 ⭐ 分水岭

**时间**：寒假 + 大二下 2-4 月 | 6-8 周
**这段最硬，也最重要。做完它，你就有一个真正的全栈项目了。**

**学**：SQLAlchemy 2.0、ORM、表关系、Argon2 密码哈希、Session Cookie、CSRF 概念、Alembic 迁移

**做**
- `users` 表、`posts` 表
- 文章 CRUD 接口
- 注册 / 登录 / 登出
- 后台页面：能写、能改、能删自己的文章

**安全点（我的主场，这里要学扎实）**
- 密码用 **Argon2**（或 bcrypt）。绝对不用 MD5/SHA1，绝不存明文
- Session Cookie 必须 `HttpOnly=True, SameSite="Lax", Secure=True`
- **不要把 token 放 localStorage** —— 任何一次 XSS 都能读走
- 理解"为什么 ORM 能防 SQL 注入"（参数化查询），而不是"听说 ORM 安全"
- **越权**：A 不能删 B 的文章。菜鸟项目最常见的漏洞，每个写操作都要验证归属

**验收**：注册 → 登录 → 发文章 → 退出 → 再登录 → 文章还在。

**里程碑**：✅ 一个能登录、能发文章的全栈项目（此时已可写进简历）

### 阶段 3 · 接大模型

**时间**：大二下 5-6 月 | 4-6 周

**学**：环境变量、`httpx` 异步请求、SSE（`StreamingResponse`）、前端 `ReadableStream`

**做**
- `/api/chat` 接口，转发到 LLM API
- 流式输出，前端逐字显示
- API 失败 / 超时的降级处理

**安全点**
- **API key 只放服务端 `.env`**，永远不进前端、不进 git（`.gitignore` 第一件事就是加它）
- 用户输入长度限制（防烧钱 + 防 DoS）
- 限流 `slowapi`，至少"同一 IP 每分钟 N 次"
- **prompt injection 初体验** —— 第一次发现"用户输入"和"指令"是同一串字符，无法用正则分开。这是我专业背景变成优势的真正起点

**验收**：对话框能流式回答，且 F12 → Network 里找不到任何 API key。

**里程碑**：✅ 一个会说话的博客

## 六、安全清单（我的专业优势，随时自查）

### 密码与认证
- [ ] 密码用 Argon2 / bcrypt，绝不 MD5/SHA1，绝不存明文
- [ ] Session Cookie：`HttpOnly` + `SameSite=Lax` + `Secure`（生产）
- [ ] token 不放 localStorage
- [ ] 登录失败提示统一（"用户名或密码错误"，不区分是哪个错——防用户名枚举）

### 输入输出
- [ ] 前端：`textContent` / `createElement`，零 `innerHTML`
- [ ] 后端：Jinja2 自动转义开着（默认开，别关）
- [ ] Pydantic 校验所有输入（类型、长度、范围）
- [ ] `response_model` 白名单，防字段泄露

### 权限
- [ ] 每个写操作都验证归属（防越权）
- [ ] 向量检索按用户过滤
- [ ] 管理接口单独鉴权

### 依赖与配置
- [ ] API key / 密钥只放 `.env`，`.gitignore` 第一个加它
- [ ] 第三方 CDN 脚本加 SRI（`integrity` + `crossorigin`），或直接自托管
- [ ] 错误信息不泄露内部细节，细节写日志
- [ ] 加 CSP 响应头

### 资源
- [ ] 用户输入长度限制
- [ ] 接口限流（尤其 LLM 接口，防烧钱）
