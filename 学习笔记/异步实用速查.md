# 异步实用速查（调度与时机的层面）

> 建立：**2026-10-16（周五）**。
> 配套两份：**[异步语法速查.md](异步语法速查.md)** 讲「语法层」（`await` / `async with` / `async for` 三套协议）；**这份**讲「调度 / 时机层」（谁被调度、什么时候开始跑、什么时候会被丢、什么时候该写 `async def`）。
> 结论全部来自本机实测脚本（在工作区，随时可删）：`_asyncio_demo.py` / `_bg_task_demo.py` / `_loop_demo.py` / `_task_count.py` / `_coro_vs_task.py` / `_task_start.py`。
> **不用记事件循环的内部构造** —— 只要记下面的结论。

---

## 一、三句骨架

1. **`async def` / `await` 是「语法」；事件循环是「运行时」。** 语法让你"能挂起"，运行时才让你"能并发" —— 所以**不 import asyncio 也能写 async/await**（循环是 uvicorn 建的）。
2. **创建 ≠ 启动。** `create_task` 只是"下单"；真正开火是**下一次让出控制权**（或你的协程结束）的时候。
3. **被调度的只有 `Task`。** 协程、异步生成器、异步上下文管理器都只是"**被 await 的东西**"，不占调度单位。

---

## 二、十条结论

| # | 结论 | 实测证据 |
|---|---|---|
| 1 | **`await` = 暂停点**（CPU 别空转）；**`create_task` = 新增一条执行线**（我别干等）。**两者配合，不是替代** | 主流程被挡 **1.52s vs 0.00s**；两种写法下观察者都照跑 |
| 2 | **父协程结束 ≠ 子任务死**（客户端断开也不影响它） | 父协程 return 后，后台任务照样跑完 |
| 3 | **它的边界 = 进程活着**：uvicorn 重启 / `--reload` / `Ctrl+C` → 丢。这叫 **best effort** | 主协程结束后剩余任务被取消 |
| 4 | 后台任务的三个坑：**留引用防 GC / 异常必须包在 task 内部 / DB session 要自己开** | 异常静默（没人 await 它，只在 GC 时警告） |
| 5 | **协程只能 await 一次；Task 能反复 await，还能 `cancel()` / `done()`** | `cannot reuse already awaited coroutine` |
| 6 | **协程在等 IO 时不占 CPU、不占线程**（只占一个对象）—— 这才是能扛上万连接的原因 | 同一循环里 1000 个连接 ≈ 1000 个对象 |
| 7 | **微任务 / 宏任务只存在于 JS**；Python 没有这个分层 | JS Console `A B C D`；Python 无对应保证 |
| 8 | **JS 创建即开始（Promise 急切）；Python 创建什么都不发生** | `checkLogin()` 不 await 也跑 vs `coro` 一行不跑 |
| 9 | **事件循环解决"等待不占线程"；线程解决"阻塞隔离 + 真并行"** | 循环里 `time.sleep(1)` → 整个循环停 1 秒 |
| 10 | **框架负责"驱动"和"翻译"；你负责"写一个能被驱动的协程"** | 见第四节 |

## 三、写代码时的 5 条速查

1. **函数体里有 `await` 吗？** 有 → `async def`；**没有 → 写 `def`**（FastAPI 会丢线程池，同步 DB 反而更安全）
2. **调异步函数** → `await`；**想后台跑 / 要能取消 / 要事后查状态** → 先 `create_task`
3. **`async with` / `async for` 只能配异步对象**（同步 `Session` 不行）；同步阻塞要用 `await asyncio.to_thread(函数, 参数)`
4. **流式接口：响应头（200 + `text/event-stream`）发出之后，出错只能 `yield` 事件，不能 `raise`**
5. **别把 ORM 对象带出 `with session`**（commit 后会被 expire → `DetachedInstanceError`），**只带值出去**（str / int / bool）

## 四、对号入座（本项目）

| 项目里的东西 | 是什么 / 谁在驱动 |
|---|---|
| `chat_stream` / `chat` 路由 | **协程**，被「请求 Task」await（框架驱动） |
| `gen()`（里面有 `yield`） | **异步生成器**，被 `StreamingResponse` `async for` |
| `rate_limit_stream`（yield 依赖） | **异步生成器**，被 FastAPI 依赖系统迭代 → 这就是「清理时机 = 最后一块产出之后」（10-11 实测） |
| `httpx.AsyncClient` / `client.stream(...)` | **异步上下文管理器** → `async with` |
| `r.aiter_lines()` | **异步迭代器** → `async for` |
| **`_spawn(_fill_title(...))`** | **本项目唯一的 Task**；`_spawn` = "下单"（create_task + 留引用） |
| `with SessionLocal()` / `session.get/scalars/commit` | **同步**（不能 `async with` / 不能 `await`） |
| 那 24 个 `def` 端点 | FastAPI 丢**线程池** → 里面的同步 DB 是安全的 |
| `chat_stream` 里的 `with SessionLocal()` | 唯一的偏差：在循环线程里做同步 DB（毫秒级，目前无感） |

## 五、JS ↔ Python 对照（两边都写的人最容易混）

| | JS | Python |
|---|---|---|
| 事件循环 | 浏览器 / Node **内置** | **`asyncio` 一个库**（uvicorn 替你启动） |
| 队列 | microtask + macrotask **两套**，且有优先级 | 只有一套（无微/宏之分） |
| `f()` 调用后 | **立刻开始跑**，返回 Promise | **什么都不发生**，返回 coroutine |
| 变成"可调度"的 | 引擎自动（续体） | **必须你 `create_task`** |
| 取消 | `AbortController`（协作式，靠对方自觉） | `task.cancel()` → **抛 `CancelledError`**（所以它不是 `Exception` 子类） |
| 未处理异常 | `unhandledrejection` | `Task exception was never retrieved` |

## 六、一句话总结

> **`await` 是"我现在照着菜谱做"（做完才往下走）；`create_task` 是"把菜谱交给厨房，我拿张取餐号继续干别的"。**
> **创建 ≠ 启动** —— 启动的开关是「控制权回到事件循环」。
> **取消不是"主协程结束"造成的，是"循环关闭"造成的** —— 而在 FastAPI 里，循环归 uvicorn，不归你的那个生成器。
