## 四、响应式三层模型

### 第 1 层 · 流动（不写断点，能盖住 90%）

**核心一句：把"写死"换成"最多 + 允许伸缩"。**

```css
/* 写死 1080 → 最多 1080 */
header nav,
header .box,
header .subject,
header .picture{
    width: 100%;
    max-width: 1080px;
}

/* 固定头那 300px 内边距 → 跟着窗口走 */
header .head{
    padding-left:  max(12px, calc((100% - 1080px) / 2));
    padding-right: max(12px, calc((100% - 1080px) / 2));
}

/* 两栏：给"理想宽度 + 允许伸缩换行"，而不是写死 640/410 */
header .box{
    flex-wrap: wrap;
    gap: 20px;
    height: auto;
}
header .box .content1{ flex: 1 1 600px; height: auto; }
header .box .content2{ flex: 1 1 380px; height: auto; }
```

`flex: 1 1 600px` 读作「我理想是 600px，但可以伸缩」：容器够宽就并排，一窄就自己换行。

**这一层改完，769–1080 的横向滚动条会消失，而一个新断点都不用加。**

#### 把写死的宽度改成什么：先看它的父容器是什么

**不能机械地全改 `width: 100%`** —— 要看父容器是不是 flex：

| 类别 | 怎么判断 | 改成什么 | 这份 CSS 里的例子 |
|---|---|---|---|
| ① 普通块级子元素 | 父容器**不是** flex/grid，它的宽度本来就该等于父容器 | `width: 100%` ✅ | `.song`(346) · `.timeline`(376) · `.control`(340) |
| ② **flex 子元素** | 父容器是 flex **行**，它旁边还有兄弟 | ⚠️ **不能写 `width:100%`**（和兄弟打架），要 `flex: 1; min-width: 0` | `.profile`(430) · `.media-name`(289) · `.count`(226) · `.login`(305) · `.timeline div`(250) |
| ③ 元素本身的尺寸 | 它就该是那个大小（头像/图标/封面） | **不要动** | `.img` 108 · `.song img` 83 · `.login a` 40.4 |

**反例**：`.column1` 是 `display:flex`（头像 108 + gap 30 + `.profile`），如果给 `.profile` 写 `width:100%` → 108 + 30 + 100% > 100% → **溢出**。所以 ② 类必须是 `flex:1; min-width:0`。

**例外**：`.column1` / `.column2` 的父 `.content1` 是 `flex-direction: column` —— 纵轴容器里子元素的宽度是**交叉轴**，`width:100%` 是对的 ✅

### 第 2 层 · 结构切换（才轮到断点）

只有"流动做不到"的事才写断点：

- `.box` 强制竖排
- 手机上头部**不吸顶**（`.head{position:static}`）
- `.picture` 的 `li` 跨列规则复位
- 导航收起 / 横向滚动

这些是**结构**，跟宽度数值无关，放哪个断点里都通用。

### 第 3 层 · 断点的位置按"内容在哪崩"定

**不要用 375 / 768 / 1024 这套"手机-平板-桌面"老名单**（那是 Bootstrap 时代的设备驱动法）。做法：**拖窗口，看到哪一宽度开始难看 / 溢出，就在那儿放一个断点。**

这一页真需要的断点大概只有 **2 个**。三个以上，就该回头想想是不是又该用流动布局了。

字号不要写死，用 `clamp()`（它本身就是"随视口连续变化"，等于不用断点）：

```css
font-size: clamp(11px, 1.6vw, 14px);   /* 最小 11，最大 14，中间跟窗口走 */
```

> **判断标准**：断点里出现"我按 375 算出来的具体数字"（8px 字号、15px padding、56px 头像），就是补丁，不是响应式。

## 五、验收清单（别用眼睛，用这三个判据）

> ⚠️ **先看这一条，2026-10-03 踩了一小时的"假 bug"**：
> **设备模拟的视口高度可能大于你屏幕能显示的高度**，于是"视口的下沿"落在屏幕外面，看起来像页面被裁了一半，**其实页面完全正常**。
> 实测数字（Edge + iPad Mini 768×1024，Windows 缩放 150%）：
> - 模拟视口高 **1024 CSS px**；窗口内容区实际只有约 **930 CSS px** → **94px 在屏幕外**
> - 屏幕里第二行只露出约 96px（该行总高 200px）→ 看起来就是"只有上半截"
> - 换 iPad Pro 13（**1376** 高）更夸张：**约 440px 在屏幕外** → "只能看到第一行的上半图"
> - 自检命令（在 Console 跑）：
>   ```js
>   scrollTo(0, 99999); console.log(scrollY + innerHeight, document.documentElement.scrollHeight)
>   ```
>   **两个数相等 = 已经滚到底，页面里没有够不着的内容** → 那就是屏幕/模拟器在骗你。
> - **正解**：① 把设备工具栏的缩放从 `100%` 改成「Fit / 自适应」；② 或换矮设备；③ **最省事：关掉设备模拟，直接拖窗口宽度** —— 垂直方向由窗口决定，不会再出现假裁切。
> - 结论：**横向用设备模拟没问题，纵向（"下面看不全"）必须关掉模拟或调缩放再判断。**

**要测的宽度**：`320 / 375 / 414 / 600 / 768 / 900 / 1080 / 1280 / 1440`
（重点补上现在完全没管的 **900** 和 **1080**）

```js
// 判据一：不横向滚动（应始终为 true）
document.documentElement.scrollWidth === document.documentElement.clientWidth

// 判据二：列出所有右边缘越界的元素（应为空数组）
[...document.querySelectorAll('header *')]
  .filter(el => el.getBoundingClientRect().right > document.documentElement.clientWidth + 1)
  .map(el => `${el.tagName}.${el.className} → right=${Math.round(el.getBoundingClientRect().right)}`)

// 判据三：固定头不压住内容（.head 的 bottom 应小于 .box 的 top）
document.querySelector('header .head').getBoundingClientRect().bottom
  < document.querySelector('header .box').getBoundingClientRect().top
```

## 六、已知的耦合与坑

1. **`.picture li div` 的高度必须由外面给。** 里面的图片是 `position:absolute`（css:535-544），**不占高度**；桌面靠 `.picture{height:600px}` + `li div{height:100%}`，手机靠 `li div{height:200px}`。
   → **顺手把 `height` 删成 `auto`，照片会全部塌成 0 高度。** 要改就用 `aspect-ratio`。
2. **`.head` 的 65px 和 `nav` 的 `margin-top:65px + top:50px` 是一对。** 断点里把 `margin-top` 改成 15px、`top:50px` 却留着 → 凭空少 50px 占位 → 搜索框和卡片重叠。手机端最省事：`.head{position:static}`。
3. **`box-sizing:border-box` 不用再写。** [base修改版.css:63-67](../static/base修改版.css#L63-L67) 已经对 `body *` 全局生效，断点里重复写是噪音。
4. **`header nav span{left:-650px}` 是桌面 hack**（输入框 672px 宽，靠负偏移把放大镜"倒推"到输入框左边，css:94-98）。手机端要换成 `position:absolute; left:14px`，现在那条 `font-size:2px` 等于把图标弄没了。
5. **DevTools 的两个误判源**：
   - 设备工具栏的 `200%` 是**显示放大**，布局宽度仍是 `375 × 667`（媒体查询按 375 算）。判断"字是不是太大"要调回 **100%** 再看。
   - 那条**红色/黄色斜纹**是 Chrome 的 **flex 覆盖层**，不是 CSS 渲染错误。判断方法看它的宽度：`header nav` 是 1080px 宽，那条带正好是 1080px 宽（1032 视口下会被切掉右边 48px）。
6. **`.picture` 的拼图是按「5 列」设计的，所以不能用 `auto-fit`。**
   证据是它自己的注释（css:448-467）：第 1 格跨 2 列、第 2 格跨 3 列 —— **"因为第一行剩余了 3 列空间"** → 2 + 3 = **5 列**；第二行第 3 格跨 2、第 4 格跨 1，也是 5。
   而 `repeat(auto-fit, minmax(190px,1fr))`（css:444）的列数是**算出来的**：`floor((容器内容宽 + 23) ÷ 213)`。

   | 容器内容宽 | `auto-fit` 给几列 | 结果 |
   |---|---|---|
   | 1080 | **5** ✅ | 拼图正常 |
   | 1032 | **4** ❌ | 跨列规则错位 |
   | 738（768px 视口，扣掉断点给的 15+15 padding） | **3** ❌ | 4 个格子排成 **3+1** → 夜间按钮卡被挤到第二行一个 **231px** 的小格里 |

   那个小格里塞着一个 **150×150 的圆**（`top:10; right:24`，css:507-518）和一个 **150px 宽、23px 字**的文字（`bottom:40`，css:524-534）→ 圆的纵向范围是 10–160，文字在 130–160，**两个直接叠在一起**。这就是"夜间模式按钮快看不见了"。

   **正解：钉死列数，不要 `auto-fit`** —— 基准 `repeat(5, 1fr)`，≤768 `repeat(2, 1fr)`，≤480 再降到 `1fr`（这时圆和文字也要跟着缩小，例如圆 `72px` + 图标 `30px` + 文字 `13px`）。
7. **`flex: 1 1 <理想宽度>` 必须配 `min-width: 0`（2026-10-01 踩过，两级都踩了）。**
   flex 子项的 `min-width` 默认是 **`auto`** = "不能小于我的**内容最小宽度**"；而 **`flex-wrap` 的换行判断用的是被 `min-width` 夹过之后的值**，不是 `flex-basis`。
   所以给 `.box` 加上 `flex-wrap: wrap` 之后：

   ```
   content1 的内容最小宽度 = 内层 .column1/.column2 的 576 + padding 64 = 640
   content2 的内容最小宽度 = 内层 .timeline 的 376      + padding 64 ≈ 454
   640 + 454 + 20(gap) = 1114  >  1080  →  换行  →  两张卡片上下排，各自 flex-grow 撑满 1080
   ```

   → **`.content1` / `.content2` 也要加 `min-width: 0`**，否则"理想宽度"被内层的写死宽度隔着两层顶穿。
   **第一次踩**：`.profile`（卡片**内部**）；**第二次踩**：`.content1`/`.content2`（卡片**之间**）。
   ⚠️ 代价：`min-width: 0` 允许它压到比内容还窄 → 里面若还有写死宽度（`.timeline` 376）就会顶出卡片。所以它和"放开内层固定宽度"要一起做。
8. **`flex-basis` 是"主轴尺寸"：主轴一翻转，`600px` 就从"宽"变成"高"（2026-10-01 踩过）。**
   证据：`.content1{flex: 1 1 600px}`（基准层）+ `@media(max-width:768px){ .box{flex-direction: column} }`（断点层）。
   到了手机上 `.box` 变纵向，**主轴 = 高度** → `flex-basis: 600px` 被解释成"**高 600px**"。
   而 `.box{height:auto}` 也救不回来：auto 高的容器没有负剩余空间，子项就按 flex-basis 取高。

   ```
   截图实测：content1 的高 ≈ 600 CSS px（899 真实 px ÷ DPR 1.5）—— 正好等于 flex-basis 的 600
   ```

   再加上 `.content1` 自己的 `justify-content: space-between`（css:127），两块内容被一个顶到顶、一个顶到底 → **中间那块大空白**（就是"content1 怎么这么空"）。

   **正解：在纵轴的断点里把 flex 简写重置**
   ```css
   @media (max-width: 768px){
       header .box .content1,
       header .box .content2{ flex: 0 0 auto; }   /* = flex: none，高度交还给内容 */
   }
   ```
   > **同类教训**：`flex:` 简写里的那个尺寸是**主轴**尺寸，方向一变含义就变。凡是"基准层横排、断点里改竖排"的地方，都要顺手重置 flex。
